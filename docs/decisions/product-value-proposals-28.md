# 제품 값 결정 제안서 (28일차)

## 배경과 범위

27일차에 만든 릴리스 종료 게이트(`docs/issue-triage-release-readiness.md`)는 종료 조건을
**"(A) 릴리스 차단 0건 + (C) 외부 입력 대기 전건 결정"**으로 정의했다. (C) 10건 중
**6건이 "제품 값 결정" 성격**이고, 사용자가 회차 시작 시 "팀이 현행 구현값을 기준으로 확정안을
올리고 팀장이 승인한다"고 답했다. 이 문서는 그 6건(I-033·I-034·I-038·I-039·I-041·I-043)의
현행 구현값을 전수조사하고 확정 제안을 담는다.

**원칙**: 새 값을 발명하지 않는다. 현행값을 그대로 확정하는 것이 기본안이고, 조사 중 같은
개념에 서로 다른 값이 박혀 있는 불일치를 발견했을 때만 어느 쪽을 정본으로 삼을지 근거와 함께
고른다.

**승인 상태(28일차 마감)**: 이 문서의 제안 6건은 **승인됐다 — `docs/prioritization-and-risks.md`
6.3절 D-083으로 확정**(승인: 팀장, 승인일 2026-07-30). 아래 "제안 1"~"제안 6" 라벨은 제출 당시
번호 없이 쓴 원문 그대로 남기고(28일차 운영 규칙 — 팀원은 D-\* 번호를 직접 붙이지 않는다, D-082),
각 절의 **"확정 권고안" 행은 이제 권고가 아니라 D-083으로 확정된 값**이다. 5건(I-033·I-034·
I-039·I-041·I-043)은 **완전 확정**이고, **I-038(제안 3)은 부분 확정**이다 — 상한(크루명 30자·
소개 300자)과 금칙어 필터의 존재·적용 계층은 확정됐지만 목록 내용·우회 표기 정책은 별도 결정
대기로 남는다. 반영 결과는 `docs/ISSUES.md`(I-033·034·039·041·043 해결됨, I-038 부분 확정으로
열림 유지)와 `docs/issue-triage-release-readiness.md`(C) 표에도 갱신했다.

**조사 방법**: 코드는 `grep`/`Read`로 직접 확인했고, DB 제약은 `mcp__supabase__execute_sql`로
`pg_constraint`(CHECK 제약)·`pg_policy`(RLS)를 조회했다. 소급 위험은 실제 `SELECT`로 위반 행
수를 셌다(2026-07-30, ref `damruradpliktkrlkakl`, `MO-IM` 프로젝트). 이번 조사는 **읽기 전용**이다
— 코드·DB 어느 쪽도 고치지 않았다.

## 제안 3 — I-038: 크루명·소개 글자 수 상한과 금칙어 필터

### 3-A. 크루명 글자 수 상한

| 항목 | 내용 |
| --- | --- |
| **현재 값** | 최소 1자 · 최대 30자 |
| **어디에 박혀 있는가** | `src/lib/rules/crew-name-validation.ts:12-13`(`CREW_NAME_MIN_LENGTH`·`CREW_NAME_MAX_LENGTH`)뿐. 호출부는 `src/lib/actions/create-crew.ts`·`src/lib/actions/update-crew-info.ts` 2곳(둘 다 같은 함수 재사용, 값 중복 없음). **DB CHECK 제약 없음**(`crews` 테이블 제약은 `crews_color_key_check`·`crews_status_check`·`crews_visibility_check` 3건뿐, name 길이 제약 없음). |
| **확정(D-083)** | **현행값 그대로 확정**: 최대 30자(displayName과 동일). **상한값은 확정 — 단, `docs/ISSUES.md` I-038은 금칙어 목록·우회 표기 정책이 남아 있어 부분 확정으로 열림 유지.** |
| **소급 위험** | **위반 1건 발견** — `crews` 14건 중 `length(name) > 30`인 행이 있다: id `c4283f8a-139c-4c69-ac4e-3c92e355e3bc`, name `"I-069 검증용 테스트 크루 (DESIGN 20일차, 재사용 금지)"`(38자), `status='archived'`. 이 행은 실제 사용자 크루가 아니라 **DESIGN이 20일차 I-069 조사용으로 만든 뒤 archived 처리한 테스트 잔재**다(이름 자체가 "재사용 금지"라고 명시). DB CHECK를 지금 추가하면 이 1건이 즉시 위반한다 — **마이그레이션 전에 삭제하거나 이름을 줄여야 한다.** 나머지 13건은 위반 없음. |
| **대안과 안 고른 이유** | 상한을 38자 이상으로 늘려 이 테스트 행을 수용하는 안은 **채택하지 않는다** — 테스트 잔재 때문에 실사용 상한을 늘리는 것은 원인과 대책이 뒤바뀐 결정이다. 대신 이 문서 보고에 "DB CHECK 적용 전 해당 archived 테스트 크루 삭제(또는 개명) 필요"를 후속 작업으로 남긴다. |
| **처리 판단(팀장 배정, 28일차 추가 조사)** | **개명은 불가능하다** — `crews_guard_archived_immutable` 트리거가 `old.status='archived'`인 행의 모든 UPDATE를 예외로 거부한다(`archived crews cannot be modified`). **삭제도 단순 1행 삭제가 아니다** — `crews`를 참조하는 8개 테이블 전부 `ON DELETE RESTRICT`이고, 이 행에는 실제로 종속 데이터가 있다: `crew_memberships` 1건·`boards` 1건·`chat_rooms` 1건·`audit_logs` 1건(`chat_messages`·`posts`·`meetups`·`invitations`·`join_requests`·`notification_preferences`는 0건). 즉 **지워도 되는 테스트 잔재가 맞지만(I-069 검증용, 실사용자 데이터 아님), 삭제하려면 이 4개 종속 행을 FK 안전한 순서로 먼저 지운 뒤 크루 행 자체를 지워야 하는 5단계 캐스케이드 삭제 작업이다.** 이번 배정(읽기 전용)에서는 실행하지 않았다 — DB CHECK 마이그레이션 착수 전 팀장 승인 하에 별도 정리 작업으로 처리할 것을 권고한다. |

### 3-C. 금칙어 필터 — "목록"이 아니라 "범위" 결정

이 항목은 지시대로 목록 내용을 새로 짓지 않는다. 결정 대상은 **"v1.0 범위에 필터를 둘 것인가,
둔다면 어느 계층에서 거를 것인가"**다.

| 항목 | 내용 |
| --- | --- |
| **현재 값(있는 그대로)** | 필터가 **존재한다.** `src/lib/rules/crew-name-validation.ts:19`의 `BANNED_WORDS`(비속어 6개: `씨발`·`병신`·`좆`·`지랄`·`fuck`·`shit`, 대소문자 무시·부분 일치)가 크루명에만 적용된다. **크루 소개(description)에는 금칙어 필터가 아예 없다** — `crew-description-validation.ts`에 해당 로직 없음, grep 확인. 코드 자체 docstring이 "검사 존재를 보이는 최소 데모 집합, 실제 운영 사전이 아니다"라고 명시한다. |
| **어느 계층에서 거르는가** | **Server Action 계층뿐이다.** `validateCrewName`은 `create-crew.ts`·`update-crew-info.ts`(둘 다 `"use server"`)에서 호출된다. **DB 제약이나 트리거로는 걸리지 않는다** — `crews` 테이블 CHECK 제약 3건 중 금칙어 관련 없음, 트리거 조회에서도 대상 없음. 우회 표기(초성 치환·유니코드 치환 등) 대응은 **없다** — 단순 대소문자 무시 부분 문자열 포함 검사뿐이라 "ㅆㅂ", "병.신" 같은 우회는 통과한다. |
| **확정(D-083, 부분)** | **v1.0 범위에 필터를 유지한다(존재 자체는 확정)**, 단 두 가지를 명시적으로 남긴다 — ① **적용 계층은 Server Action(앱 레이어)으로 유지**한다(DB 트리거로 승격하지 않는다). 이유: 이 필터는 앞으로 목록이 자주 바뀔 운영 데이터에 가깝고(팀장 인계 메모도 "코드 하드코딩은 배포 없이 갱신 불가"라고 지적), DB 트리거로 옮기면 목록 갱신마다 마이그레이션이 필요해져 오히려 갱신을 더 무겁게 만든다. ② **목록 내용(단어 자체)과 우회 표기 대응 정책은 이번 제안의 확정 대상이 아니다** — 그건 법무·운영 정책 확인이 필요한 별도 결정이며, 지금 6단어 데모 집합을 "확정"하면 팀이 임의로 금칙어 사전을 만든 것이 된다. **D-083으로 확정된 것: 필터 존재(v1.0 유지)·적용 계층(Server Action). 미결로 남는 것: 금칙어 목록 내용·우회 표기 대응 정책 — 이 둘이 남아 있어 `docs/ISSUES.md` I-038은 "해결됨"이 아니라 "열림, 부분 확정"으로 갱신했다.** |
| **소급 위험** | 없음(N/A) — 이 항목은 DB 제약이 아니라 앱 레이어 검사이므로 과거 데이터를 소급 위반시키지 않는다. 다만 참고로 `crews` 14건의 name·description에 현재 `BANNED_WORDS` 6개가 포함된 행은 없다(육안 확인, 시드 크루명이 전부 정상적인 취미 크루명). |
| **대안과 안 고른 이유** | ① 필터를 v1.0에서 아예 제거(v0.2로 이월) — FR-010 예외 흐름 E3가 "금칙어 포함 → 거부"를 명시적으로 요구하므로 요구사항 위반이 되어 채택 안 함. ② DB 트리거로 승격 — 위에서 설명한 갱신 비용 때문에 채택 안 함. ③ 크루 소개(description)에도 즉시 같은 필터를 추가 — 이번 조사에서 "없다"는 사실만 확인하는 것이 임무이고, 추가는 코드 변경(이번 배정 범위 밖)이라 별도 후속 항목으로만 남긴다. |

## 제안 4 — I-039: 권한 매트릭스에 "채팅방 열람" 행을 신설할지

이 건은 값이 아니라 **매트릭스 표기 범위**의 문제다. v0.2 "읽기 전용 크루원" 역할을 지금
구현하는 게 아니라, 매트릭스에 행을 추가할지만 판단한다.
