## 회차 운영 사고 — 서브에이전트 4명 전원의 보고 채널 유실

**네 명 모두 작업은 정상 수행했으나 완료 보고를 반환하지 못했다.** 유휴 통지(`idle_notification`)만 반복했고, 팀장이 보낸 확인·수정 요청에도 응답하지 않았다. 팀장이 `SendMessage`로 세 차례 시도했으나 회신은 0건이었다.

**대가**: 교차검증 루프(리뷰 짝 간 상호 점검)를 계획대로 돌리지 못했다. 팀장이 CREW에 DESIGN 검증을 배정했으나 회신이 없어, **교차검증을 팀장이 직접 수행**했다(아래).

## 이번 회차가 남긴 운영 규칙

1. **"통과"를 반환하는 도구 자체를 매 회차 검증한다.** `tsc --noEmit`은 다른 팀원의 dev 서버가 살아 있으면 **의미 분석을 통째로 건너뛴 채 exit 0을 반환할 수 있다**(I-129). 회차 마감 테스트 전에 dev 서버를 정리하고, 의도적 타입 오류를 주입해 실제로 잡히는지 확인한 뒤 원복한다. 이번 회차에 실제로 수행했다.
2. **정적 스캔 결과를 그대로 수정으로 옮기지 않는다.** CREW가 후보 9개 중 5개를 "구조적으로 도달 불가"로 판정해 고치지 않았다 — 도달 불가를 증명하는 것이 고치는 것보다 값지다. **없는 결함을 고치면 코드가 늘고 근거는 남지 않는다.**
3. **핵심 트리거 함수를 처음으로 새 방식으로 호출할 때는 기존 가드가 자기 파이프라인을 막는지 먼저 본다.** `finalize_closed_poll`은 지금까지 `meetups`에 INSERT만 해 와서 UPDATE 가드에 한 번도 걸린 적이 없었다 — **"한 번도 걸린 적이 없다"가 "걸리지 않는다"를 뜻하지 않는다.**
4. **"코드를 고쳤는데 브라우저 동작이 그대로면 먼저 dev 서버를 재시작한다"**(I-135). WSL2 drvfs 마운트에서 Turbopack 파일 워처가 변경을 놓칠 수 있다. 이 가정을 의심하지 않으면 "고쳤는데 왜 그대로냐"는 오판정으로 이어진다.
5. **빈 테이블에서 한 검증은 검증이 아니다.** `reports`가 0건인 채로 상태 탭을 클릭하면 네 탭이 전부 비어 "구분된다"를 확인할 수 없다. **각 분기에 실제로 데이터를 넣고 서로 다른 결과가 나오는 것**을 봐야 한다(24일차 FR-055 오판정·25일차 DESIGN의 임시 신고 8건과 같은 교훈의 세 번째 반복).
6. **팀원은 판정 근거를 산출물 안에 남긴다 — 보고 채널은 유실될 수 있다.** 이번 회차에 네 명 전원의 보고가 유실됐으나 회차가 성립한 이유는 각자가 결정 문서·기준선 §8·초안 이슈에 **근거와 원시 출력**을 남겼기 때문이다. "통과했다"만 적었다면 아무것도 검증할 수 없었다.
7. **문서의 번호 카운터는 팀장이 회차 마감마다 grep으로 대조한다.** "다음 결정 번호"가 실제 최댓값과 **5** 어긋나 있었다 — 이 파일이 스스로 경고하는 드리프트인데도 재발했다. 자동 강제 장치가 없으므로 마감 절차에 넣는다.
