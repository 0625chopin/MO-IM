## D-074 — 팀장 결정이 자기반증으로 뒤집힌 건

CREW가 기준선 문서에 "결정 후보"로만 남긴 것(스키마 전체에 `alter default privileges ... revoke execute on functions from anon, authenticated`)을 **팀장이 적용 결정했다.** 근거는 ① 24일차 I-111에서 테이블에는 이미 같은 조치를 했으니 함수만 열어 두는 건 일관성이 없다 ② 잠그면 GRANT 누락이 `42501`로 시끄럽게 드러나고 안 잠그면 REVOKE 누락이 조용히 권한을 연다 ③ 미래 객체 한정이라 기존 45개 함수에 무영향이었다.

**그리고 그 결정은 이 환경에서 성립하지 않았다.** 팀장이 함께 지시한 자기반증(새 함수를 만들어 EXECUTE가 안 붙는지 확인)에서 CREW가 잡아냈다 — `pg_default_acl`에는 의도대로 저장된 것처럼 보였지만, **검증 전용 스키마에 새 함수를 만들어 `pg_proc.proacl`을 직접 조회하니 `PUBLIC` EXECUTE가 매번 자동으로 붙어 있었다.** `PUBLIC`은 anon/authenticated를 포함하므로 실질적으로 전혀 잠기지 않은 상태였다. Supabase 공식 문서 구문을 포함해 5가지 이상 조합을 시도했지만 전부 동일했고, **원인은 특정하지 못했다**(`public` 스키마 소유자가 `pg_database_owner`인 점, `postgres`가 `rolsuper=false`인 점을 후보로 확인했으나 인과까지는 못 밝혔다 — 추정을 결론으로 올리지 않았다).

**CREW는 원복을 택했다** — "효과 없는 변경을 '적용했다'고 기록하면 다음 회차 기준선 대조에서 거짓 안도감을 준다." 잠기지 않은 문을 잠갔다고 적은 문서는 아무것도 안 적은 문서보다 나쁘다.

**팀장 판단의 결함**: "테이블에 같은 조치를 했으니 함수도 일관되게"는 **테이블과 함수의 기본 권한 메커니즘이 다르다는 것을 고려하지 않은 유추**였다. 함께 지시한 자기반증 절차가 없었다면 잠기지 않은 문을 잠갔다고 기록한 채 회차가 끝났을 것이다.

**실무적 결론**(D-074에 명시): 기본권한 메커니즘으로는 이 잠금을 자동화할 수 없고, **이 프로젝트가 써 온 "함수 생성마다 그 마이그레이션 안에서 명시적 per-function REVOKE" 관행이 유일하게 검증된 차단 수단**이다. CREW가 임시 함수로 실 REST 재확인까지 했다(anon `401 42501` / 명시 GRANT 받은 authenticated `200`).

## 이번 회차가 남긴 운영 규칙

1. **`flock` 안에서 장기 실행 서버를 백그라운드로 띄우지 않는다.** CORE가 `flock ... -c "npm run build && nohup next start & disown"`을 돌렸더니 **`disown`해도 next-server가 flock의 lock fd를 상속해 서버가 사는 동안 빌드 락을 계속 쥐었다** — 다른 팀원 빌드를 전부 막을 뻔했다. 빌드와 서버 기동을 별도 명령으로 분리한다. CORE가 스스로 발견·신고했고 이후 재발하지 않았다.
2. **이슈 등재 창구를 팀장으로 단일화했다 — 이번 회차 충돌 0건.** 24일차에 네 번 난 번호 충돌의 원인은 grep과 쓰기 사이의 간격이라 "등재 직전 재확인"으로는 막을 수 없었다. 팀원은 `docs/ISSUES.draft.<NAME>.md`에 번호 없이 쓰고 팀장이 회차 말에 병합한다. **구조를 바꾸니 문제가 사라졌다.**
3. **MCP 공유 브라우저 프로필은 회차당 한 명만 쓴다 — 그리고 반드시 `browser_close`로 닫는다.** DESIGN이 15분 넘게 8회 재시도하며 막혔고, 진단 결과 **`SingletonLock` 파일 상태와 실제 오류에 상관관계가 없었다**(파일이 사라진 직후에도 실패) — 원인은 파일 락이 아니라 **다른 세션(CREW)이 붙잡고 있던 CDP 연결**이었다. **해법은 `node_modules/playwright`로 격리 Chromium을 직접 구동하는 것**이다(Task 033·037 전례, BOARD가 오늘 그 방식으로 신고 3종 실측을 마쳤다). 반복 작업(19라우트 × 2테마 × 3뷰포트)은 스크립트가 MCP 대화형보다 빠르다.
4. **팀원은 서로의 보고를 볼 수 없다 — 중계는 팀장 책임이다.** BOARD가 이미 해결한 브라우저 우회법을 DESIGN이 몰라 같은 벽을 혼자 15분간 두드렸다. 한 팀원이 환경 문제를 우회하면 팀장이 즉시 다른 팀원에게 전달해야 한다.
5. **공유 `.next`는 여전히 취약하다.** BOARD가 다른 팀원 dev 서버가 `.next/dev`를 손상시킨 채 종료한 것을 발견하고 **남의 프로세스는 안 건드린 채 캐시만 지워 자체 복구**했다. 이 대처가 옳다.
6. **"적용했다"와 "효과가 있다"는 다르다(D-074).** 설정이 저장됐는지(`pg_default_acl`)가 아니라 **실제 결과 객체에 무엇이 붙는지**(`pg_proc.proacl`)를 봐야 한다. 마이그레이션을 적용하는 모든 회차에 자기반증을 요구한다.
7. **문서의 집계 숫자는 원시 출력에서 직접 세어 옮긴다.** 기준선 3곳 불일치는 DB 변화가 아니라 **원시 결과를 산문으로 옮겨 적을 때의 계수 오류**였다. 숫자를 손으로 옮기는 순간이 오류 지점이다.
